# 官方 NVENC 更新核对与升级残留清理

记录日期：2026-10-23。本轮只核对上游资料、当前机器状态并清理已被替代的升级文件，**没有安装新驱动，也没有撤掉当前 2.3.7 的实验性覆盖包**。

## 官方支持已经变化

GitHub Release API 当日返回的最新正式版为 [v2.5.3](https://github.com/nullmoth/nvidia-macos-driver/releases/tag/v2.5.3)，发布于 2026-10-22 11:36:41 UTC，固定提交 `75e2e28a55fef0e3c3001235c6d28c8cfae0019a`。以下来自该版本的[固定更新日志](https://github.com/nullmoth/nvidia-macos-driver/blob/75e2e28a55fef0e3c3001235c6d28c8cfae0019a/CHANGELOG.md)，不是这台机器的新硬件验收：

| 版本 | 与本机相关的变化 |
| --- | --- |
| 2.4 | 官方加入 RTX 20 / 30 的 H.264 与 HEVC 硬件编码，按显卡自动选择；修复 Tahoe 图标和玻璃界面 |
| 2.4.2～2.4.4 | 先后修复启动黑屏、登录后冻结 / 内核线程耗尽，以及两台 RTX 3060 上的 WindowServer 非法句柄崩溃 |
| 2.5.0 | NVIDIA 内核驱动和 GSP 从 610.57.04 更新到 615.78.08；旧补丁不能直接跨版本套用 |
| 2.5.1 | 修复部分 CoreAnimation 视频格式、HiDPI / 缩放显示，并改进 CPU 绘制表面的上传路径 |
| 2.5.3 | 修复 2.5.0～2.5.2 使用 `nvregdwords=` 时的启动 panic；明确 macOS 26 已移除 AppleHDA，本包自身不能提供 HDMI / DP 声音 |

因此，**官方新版已有我们此前为 3060 补回的硬编功能，下一轮应优先验收完整官方包**。这不等于新版本已在本机通过：本次 SSH 仍读回 macOS 26.7.1 / 25G241、驱动 2.3.7，光梭主机进程继续运行。没有用 release 声明替代像素校验，也没有宣布 HEVC 已能正确输出。

实际迁移时先保存包含最新用户数据的当前 26 冷备，核对固定包及清单，再按实际 OS 安装对应基础驱动 / AuxKC，复验 Metal、VideoToolbox 硬件标志、H.264 解码像素、持续性能、光梭和电源。通过后再将旧覆盖包退出当前流程；不能先从正在使用的 2.3.7 中删掉编码库，也不能在官方新版上重套旧地址 / 旧二进制。

## 已完成的清理

按用户要求删除三类不再被 VM 引用的文件：

- Tahoe 准备阶段保存的原 15 升级前完整冷备。
- 实际运行安装器前保存的 26 克隆检查点。
- 26.7.1 安装目录中的 InstallAssistant 包、正常和失败格式化的介质镜像、分片及下载元数据。

删除前检查所有 VM 的活动 / 持久定义、磁盘 backing chain、loop 设备、嵌套挂载及打开文件，确保不引用目标；对绝对路径执行白名单与 realpath 核对。当前 26 最终完整冷备的元数据 SHA256 全部通过，qcow2 检查无错误、无 backing，且与活动系统盘为独立 inode。删除前保留了小型元数据私有归档，**不保留已删除系统镜像本体**。

清理脚本前后读回的可用空间为 563,165,470,720 → 630,393,999,360 字节，即当次确认释放 **67,228,528,640 字节，约 62.6 GiB**。稍后 `df -h` 读到约 595 GiB 可用；在线文件系统可用量会继续变化。目录 `du` 大小不能直接相加当作释放量，因为 reflink 备份之间共享数据块。

保留内容：当前运行的 26 系统与 EFI、原 15 VM、26 升级完成后的最终完整冷备、较早的 2.3.6 / 2.3.7 驱动冷备，以及引导配置和恢复工具。整个清理没有关闭或重启当前 VM，也没有修改驱动、Apple 身份或 TCC。

**第 14 / 15 章及 10 月 19 日结果是历史快照。**其中当时“安装前检查点仍保留”的描述不再代表当前库存；今后恢复优先核对实际文件，不尝试按已删除的旧路径恢复。保留的最终备份仍在同一物理存储上，不是抗磁盘故障的异地副本。
