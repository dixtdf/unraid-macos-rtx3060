# 官方 2.5.3 升级：退出实验性 NVENC 覆盖

日期：2026-10-23。用户明确要求直接升级、跳过新增备份；本轮**没有新增 VM 冷备份**，保留既有恢复点，使用未修改的官方安装器及其自带组件回退机制。没有修改 EFI、Apple 身份、远控应用或 TCC。

## 固定输入与安装

- 目标：[v2.5.3](https://github.com/nullmoth/nvidia-macos-driver/releases/tag/v2.5.3)，提交 `75e2e28a55fef0e3c3001235c6d28c8cfae0019a`。
- 官方包：`nullmoth-nvidia-2.5.3.tar.gz`，264,067,652 字节，SHA256 `6ec9d23f8d7e0ab340b9e0a9753f7c48722b9930118fff648d545e0b95016884`；本地和 Mac 校验均通过。
- 包内 120 个归档条目，经路径和链接审查；两条 Vulkan 符号链接均指向包内文件。67 项 manifest 全部严格校验通过。
- 安装前为 macOS 26.7.1 / 25G241、2.3.7 + 实验性 NVENC；核对实际启动盘为当前 26 VM 后执行官方安装器。

安装器从 root 所有的私有副本校验运行时，试建 AuxKC 后完整替换驱动、用户态 bundle 和固件，再生成实际 AuxKC。旧实验性覆盖随完整 bundle 替换退出；没有先拆除正在使用的编码库，也没有向新版重套旧补丁。官方安装器保留旧组件并生成启动回退任务；这不是本轮新增完整 VM 备份，不保证恢复近期用户数据。

安装成功后正常重启。macOS 启动时间实际更新为 2026-10-23 15:41:53 中国标准时间；四项 NVRM / NVAccel / NVRMFB / NVRMAGDC 均实际加载为 2.5.3，控制台用户恢复，bootguard 记录桌面持续运行并将此次启动计为成功。

## 探针适配与失败记录

旧独立探针只查找已加载的 `libnvenc_h264.dylib`。2.5.3 在本机实际选择 `libnvenc_h264_ga10x.dylib`，因此首轮在编码器创建成功后以 `loaded_encoder_hash_unavailable` 停止，尚未编码任何帧。这不是一次像素失败，也不跳过来源校验。

本轮只修改私有诊断探针的已加载库名匹配为 GA10x，重新构建 / 签名并置于 root 所有的诊断目录；硬件要求、1920×1080 NV12 输入、独立解码、像素容差、强制 IDR 和性能门槛保持原样。较早一次脚本传输的 CRLF、一次探针所有权保护拒绝也都发生在原生测试前，修正后另建报告目录，没有修改驱动来迎合测试。旧失败报告保留。

实际加载 GA10x 库 SHA256：`f67d08ba1689f0c5eb64408fc3f4a2b8a3246800245bc976e16b4bffdc5b31b3`，匹配官方清单。持续资格报告 SHA256：`888600763c5d5fec72779e99c56cff82a9ea17ba9d69656cce1dd8ffd5f60a8a`。官方通用库、NVMTL 与 os26 NVAccel 的安装后字节也已同包核对，不混用 2.3.7 摘要。

本轮已使用官方 2.5.3 的 H.264 NVENC，无需旧实验性覆盖。HEVC 虽在官方支持声明中，尚未在本机做本轮像素验收；Apple ID、其他图形 API、实际音频内容和端到端延迟也未重测。没有为本次升级额外清理旧恢复点，前次删除库存仍见[第 16 章](16-upstream-native-nvenc-and-cleanup.md)。未来回退须区分旧完整 VM 恢复点的日期与本次安装器组件备份，不把较旧系统镜像直接覆盖当前用户数据。
